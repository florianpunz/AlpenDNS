# External Integrations

**Analysis Date:** 2026-10-20

## APIs & External Services

**DNS Upstream Resolvers:**
- Configurable resolvers in `[[upstream_pool]]` (`config/alpendns.example.toml`); no provider is hard-coded.
- Transports (`crates/alpendns/src/config.rs`, `crates/alpendns/src/upstream/transport.rs`):
  - `dot://` DNS over TLS, default port 853.
  - `doh://` DNS over HTTPS, default port 443, default path `/dns-query`.
  - `doq://` DNS over QUIC, default port 853.
  - `udp://` cleartext is rejected in `upstream_pool` at startup and allowed only in `[[forward_zone]]` for a nameserver in the local network.
- SDK/Client: `hickory-net` 0.26.1 (`DnsExchange`, `tls_exchange`, `HttpsClientStream`, `QuicClientStream`, `DnssecDnsHandle`).
- Auth/trust: TLS server certificate checked against configured `tls_name` and compiled-in Mozilla roots (`webpki-roots`); no API keys. DNSSEC chain is recomputed locally by default (`privacy.dnssec = true`, ADR-0016).
- Selection: `split_by_zone` hashes the registrable domain (Public Suffix List) to one resolver; seed rotated every `seed_rotation` (default 24h). No fan-out; next resolver only on failure (`crates/alpendns/src/upstream/strategy.rs`, `pool.rs`).
- Timeout: overall client query timeout `server.query_timeout` (default `"3s"`).

**Oblivious DoH (ODoH, RFC 9230):**
- Optional proxy in `privacy.odoh.proxy`, URL must be `https://` (`crates/alpendns/src/config.rs`).
- Client: `reqwest` HTTPS POST with `Content-Type`/`Accept` from `odoh-rs`; proxy URL receives `targethost` and `targetpath` query parameters (`crates/alpendns/src/upstream/odoh.rs`).
- Key discovery: once per process, direct HTTPS GET to `https://<target-host>/.well-known/odohconfigs`; the target host is pinned to a configured IP address via `reqwest::ClientBuilder::resolve` so key fetch needs no DNS lookup of its own. This one connection bypasses the proxy (documented deviation, ADR-0017).
- Auth: no API key; proxy/target are chosen by the operator, and all resolvers in the pool must use `doh://` or startup fails.

**Blocklist and Allowlist Sources:**
- `[[blocklist]]` and `[[allowlist]]` entries accept exactly one of `url` or `path` (`crates/alpendns/src/config.rs`).
- `url`: HTTP or HTTPS GET (`reqwest` 0.13.1 with `rustls-no-provider` + `webpki-roots`); user agent `alpendns/<version>`; 60 s timeout; 64 MiB cap enforced both on `Content-Length` and incrementally while streaming (`crates/alpendns/src/filter/source.rs`).
- Conditional requests: sends `If-None-Match` (ETag) and `If-Modified-Since` (Last-Modified); handles HTTP 304 from the on-disk copy.
- `path`: local file, same size cap.
- Refresh: `[[blocklist]].refresh` schedule through `policy::run_updater` (`crates/alpendns/src/policy/mod.rs`); a failed update keeps the previous rule set (fail open on availability).
- Examples in the reference config: `https://raw.githubusercontent.com/StevenBlack/hosts/master/hosts`, `https://big.oisd.nl/domainswild`; local allowlist `/etc/alpendns/allow.txt`.

**Newly Registered Domains (NRD) Feed:**
- Interface is a file, not an API call: `detection.nrd.source`, default example `/var/lib/alpendns/nrd.txt`.
- Format: one `domain<TAB/whitespace>YYYY-MM-DD` per line, `#` comments, extra columns ignored (`crates/alpendns/src/detect/nrd.rs`).
- Producer is the external AlpenShield project; if the file is missing the detector stays off and the resolver continues.

**API and Web UI:**
- HTTP server on `api.listen` (default `127.0.0.1:8053`), built with `axum` (`crates/alpendns/src/api/mod.rs`).
- API routes (token-protected):
  - `/api/status`, `/api/top`, `/api/history`, `/api/explain`, `/api/recent`, `/api/lists`, `/api/policies`
  - `/api/allow`, `/api/allow/{domain}`, `/api/deny`, `/api/deny/{domain}`, `/api/flagged`
  - `/api/events` — Server-Sent Events stream (`async-stream`)
- Static UI routes (unauthenticated, contain no data): `/`, `/app.css`, `/app.js`, embedded from `web/` via `include_str!` (`crates/alpendns/src/api/ui.rs`). The page asks for the token on first use and sends it with API requests.
- The UI makes no external requests: no CDN, no external fonts, no analytics (CLAUDE.md B.6).

**Prometheus Metrics:**
- Separate listener on `metrics.listen` (default `127.0.0.1:9153`), path `metrics.path` (default `/metrics`) (`crates/alpendns/src/metrics.rs`).
- Text exposition format generated by hand; no metric library and no push gateway.
- No token on this endpoint by design, because it contains no query names; labels are limited to configuration-derived names and RCODEs.

## Data Storage

**Databases:**
- None. There is no database server, ORM or embedded database in the current code. All runtime state is in memory (`docs/ARCHITECTURE.md` §9).
- `/var/lib/alpendns/stats.redb` appears in the architecture document only as an optional future persistence idea; no `redb` dependency or implementation exists in `Cargo.toml` or `crates/alpendns/src/`.

**File Storage:**
- Blocklist cache: `/var/cache/alpendns/lists/<sanitized-name>.list` and `.meta` (ETag/Last-Modified). Written atomically; used when the network fetch fails (`crates/alpendns/src/filter/source.rs`).
- Query log: `/var/log/alpendns/queries.jsonl`, JSON Lines, only when `privacy.logging.mode = "full"`; rotated by `packaging/logrotate/alpendns` with `copytruncate` and `rotate 7`.
- State directory `/var/lib/alpendns/`, created by systemd `StateDirectory`; holds the optional NRD feed.
- Configuration and token under `/etc/alpendns/`.

**Caching:**
- In-process DNS answer cache (`crates/alpendns/src/cache.rs`, `caching.rs`) with LRU eviction, serve-stale (RFC 8767) and prefetch; no external cache such as Redis or Memcached.

## Authentication & Identity

**Auth Provider:**
- None; no external identity provider, OAuth, OIDC or LDAP integration.

**API Authentication:**
- Bearer token read from `api.token_file` (default `/etc/alpendns/api.token`).
- If the file is missing or empty, a 32-hex-character token is generated at startup and written with mode `0600`; existing files are tightened to owner-only if group/other permissions are present (`crates/alpendns/src/main.rs`).
- Token accepted as `Authorization: Bearer <token>` or as a `token=` query parameter (needed because browser `EventSource` cannot set headers); comparison is constant-time (`crates/alpendns/src/api/mod.rs`).
- The static UI routes `/`, `/app.css`, `/app.js` are deliberately outside the auth layer; they contain no data.
- Metrics endpoint has no authentication and is intended for loopback scraping.

**DNS Client Identity:**
- Implemented: client IP / subnet matching (`ipnet`, `crates/alpendns/src/policy/clients.rs`).
- Planned but not implemented: DoH path tokens and mTLS (`[[client]].match.doh_token`, `server.doh` in `config/alpendns.example.toml` are marked `[PHASE 3+]`; no encrypted client listeners exist yet).
- DNS clients themselves are not authenticated; rate limiting per IPv4 address / IPv6 `/64` is the only admission control (`crates/alpendns/src/ratelimit.rs`).

## Monitoring & Observability

**Error Tracking:**
- None. No Sentry, no crash reporting, no telemetry outbound (CLAUDE.md B.1 rule 4).

**Logs:**
- `tracing` with structured fields to stdout/journald, filtered by `RUST_LOG` (default `info`) (`crates/alpendns/src/main.rs`).
- Decision traces leave the pipeline through `server::handle_request` → `logging::QueryLog`; the configured mode (`none`, `aggregate`, `ring`, `full`) decides retention (`crates/alpendns/src/logging/mod.rs`).
- Metrics exposed for Prometheus scraping; the process never pushes metrics.

**UI:**
- Server-Sent Events at `/api/events` feed the live web UI.

## CI/CD & Deployment

**Hosting:**
- Debian package installed on the operator's own host; no cloud runtime dependency.
- GitHub Releases carry the built `.deb` files.

**CI Pipeline:**
- `.github/workflows/ci.yml`:
  - `check`: `cargo fmt --all --check`, `cargo clippy --all-targets --all-features`, `cargo test --all-features`, with `RUSTFLAGS: "-D warnings"`.
  - `deny`: `EmbarkStudios/cargo-deny-action@v2`, weekly schedule plus push/PR; on failure it opens or comments on a single GitHub issue.
  - `fuzz`: nightly toolchain, `cargo-fuzz`, each of the four targets for 120 s.
- `.github/workflows/release.yml`: on push to `main`, builds `cargo deb -p alpendns` on amd64 and arm64, checks `Cargo.toml`/`Cargo.lock` version equality and tag uniqueness, then `gh release create`.
- `.github/workflows/pages.yml`: builds and publishes the static UI demo from `web/demo/build.sh` to GitHub Pages.

**Packaging integrations:**
- systemd unit `packaging/systemd/alpendns.service` (ordering after `network-online.target` and `time-sync.target`, `ExecStartPre=alpendns ... check`, hardening directives).
- Debian maintainer scripts `packaging/debian/postinst`, `prerm`, `postrm` (create service user, start on first install, purge removes state).
- `cargo-deb` metadata in `crates/alpendns/Cargo.toml` installs binary, config, logrotate rule and documentation; config files marked as conffiles.

## Environment Configuration

**Required env vars:**
- None required for operation.
- Optional: `RUST_LOG` (default `info`).
- Build-time: `RUSTFLAGS` is set to `-D warnings` in CI; `ALPENDNS_CORPUS_DIR` optionally points measurement tests at a corpus directory.

**Secrets location:**
- API token: `/etc/alpendns/api.token` (file, mode `0600`), path configurable via `api.token_file`.
- No secrets in environment variables, no `.env` file, no committed credentials.
- TLS material for encrypted client listeners is referenced in the target config (`server.doh.cert`/`key`) but that listener is not implemented.

## Webhooks & Callbacks

**Incoming:**
- None. GitHub Actions receive GitHub's own webhooks; AlpenDNS itself exposes no webhook endpoint.

**Outgoing:**
- None. The process initiates only the configured DNS upstream connections, the configured blocklist/allowlist HTTP(S) downloads, and the ODoH proxy/key configuration requests.
- No telemetry, update check, crash reporting or analytics connections (CLAUDE.md B.1 rule 4; `reqwest` is built without system proxy support).

## Integration Constraints

- Cleartext DNS outbound is a startup error except explicitly configured `forward_zone` entries (`udp://`), which are expected to point into the operator's own LAN.
- All outbound TLS uses `rustls` with `ring`; system certificate store and system proxy are deliberately not used.
- The Public Suffix List is compiled into the binary (`psl`), so upstream splitting needs no network fetch.
- Tests never contact real upstream resolvers or blocklist URLs; fakes run in-process (`crates/alpendns/tests/integration.rs`, `docs/TESTING.md` §4).
