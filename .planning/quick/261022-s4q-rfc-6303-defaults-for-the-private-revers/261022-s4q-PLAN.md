<objective>
Compile the RFC 6303 §4 reverse-zone list (33 entries: 25 IPv4 `in-addr.arpa`,
8 IPv6 `ip6.arpa`) into `LocalBackend` as a built-in fallback that answers
NXDOMAIN without a synthetic SOA. The built-in is consulted only when no
configured `[[local_zone]]` or `[[forward_zone]]` claims the name; a configured
zone always wins, and `Config::validate` keeps seeing only configured entries so
existing configurations keep starting. Add the operator migration note and the
decision record.

Purpose: close the privacy leak where a PTR query for a private address
(`192.168.1.5`) leaves the house, and end the upstream-dependent
NXDOMAIN/SERVFAIL churn for those ranges (docs/TODOS.md item 11).
Output: a locally answered private reverse space, existing configs unchanged,
documentation that says so.

Locked decisions from CONTEXT.md (do not revisit):
- List scope — full RFC 6303 §4, IPv4 and IPv6.
- Answer type — NXDOMAIN without a synthetic SOA, exactly as
  `LocalZone::is_closed` answers today. No new message synthesis.
- Override and validation — a configured zone wins; `Config::validate` sees only
  configured entries; existing configs keep starting.
- No switch to disable the default. No PTR records derived from `local_zone`
  A records (ADR-0023).
</objective>

`let Some((_, label)) = self.builtin.iter().find(|(z, _)| z.zone_of(query.name()))`.
Build the response with the existing `response_to(request)`, set
`response.metadata.response_code = ResponseCode::NXDomain`, record
`Step::LocalAnswer { zone: Arc::clone(label), records: 0 }`, and return. Copy
the closed-zone branch's shape exactly: no SOA, no `AA` (response_to already
guarantees both). Use `Name::zone_of`, never string `ends_with`.

(c) `rfc6303_an_ipv6_private_reverse_name_is_answered_locally` — one
