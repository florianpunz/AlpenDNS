<objective>
Serve a "Blocked by AlpenDNS" page from a dedicated, unauthenticated HTTP
listener on port 80. A name answered with `blocking.mode = "sinkhole"` points
the browser here; the page shows the blocked name, says it was blocked locally
on this network, and names the matched blocklist. It shows nothing else about
the installation. The listener is HTTP only, off by default, and the shipped
default block mode stays `nxdomain`.

The reason comes from the existing decision trace, not a second source of truth:
`policy::block_cause` runs the same evaluation as the DNS path with
`Effects::ReadOnly`, so a page view neither counts in DNS statistics nor feeds
the tunneling detector's window. The typed `Step` decides which list matched;
rendered explanation strings are never parsed.

Purpose: close the loop that `Sinkhole` already opens. The DNS half has existed
since phase 4; this is the missing HTTP answer, as an opt-in operator choice
(docs/TODOS.md item 8).
Output: a second open listener, a static page in the established design
language, a strict defaulted config section, and the operator recipe.

Locked decisions from CONTEXT.md (do not revisit):
- Own listener on port 80, unauthenticated, serving only the block page. Never a
  route on the token-protected API listener.
- HTTP only. No TLS, no certificate, no key storage, no port 443.
- Content is the blocked name, the fact that it was blocked locally on this
  network, and the matched list name. No client IP, policy name, rule text,
  allow/block controls or UI link.
- The shipped default stays `blocking.mode = "nxdomain"`; `[block_page]` defaults
  to `enabled = false`.
- The page reuses `web/app.css`; `data-theme` is set from `matchMedia` in a small
  head script, exactly as `web/index.html` does. No `prefers-color-scheme` colour
  block and no `light-dark()`.

Out of scope; stop and report if a step reaches one: TLS or port 443, a new
dependency, rewriting statistics ownership inside `Engine::evaluate`, per-client
pages, a theme toggle, or a second listen address.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN client → block-page listener (:80) | Unauthenticated HTTP input crosses here: `Host` header, path, peer address. Everything from it is hostile. |
| block page → policy engine | The page asks the in-process engine for a verdict; the answer must not mutate DNS state. |
| block page → logs | The name must not cross into any log; it may leave only in the HTTP response to the requester. |
