<objective>
Fix review finding WR-05: `policy::explain` claims to be a simulation but runs the
counting evaluation, so every `/api/explain` click in the UI and every
`alpendns policy test` increments the live `blocked`/`allowed`/`passed` counters
and feeds the heuristics, polluting metrics and the sampled history. The private
`Effects` switch has one axis where it needs two: it conflates "may I count" with
"may I consult the heuristics", and exactly one site uses the second axis.

Split the switch into two independent gates and make each path state what it
really does. Then make the three doc sites and any operator documentation say
what the code actually does.

Purpose: a read-looking endpoint must not move the numbers an operator watches,
and a name a heuristic blocks must still be explained as blocked. Both properties
have to hold at once, so the switch needs two axes instead of one mode.

Output: a two-field `Effects`, three named modes wired to the three callers, a
new integration test that pins all six counter branches and the detector pin, and
documentation that no longer overclaims.

Locked decision (user, 2026-10-30) — do not revisit:
- `explain` keeps running the detectors; only the counting stops.
- Modes: DNS path (`evaluate_typed`, `PolicyBackend`) count = true, detectors =
  true, unchanged; `explain` count = false, detectors = true; `block_cause`
  count = false, detectors = false, unchanged.
- The shape of the switch is ours to choose, but the two axes must be independent
  and the call sites readable.

Out of scope; stop and report if a step reaches one: making `explain` fully
read-only (that is the rejected alternative), gating `inspect_answer` /
`PolicyBackend` (rebinding runs only in the DNS path and is unchanged), changing
detector thresholds, actions or defaults, adding an API or live-binary test
harness, touching the block page's behavior, or adding a dependency.
</objective>
